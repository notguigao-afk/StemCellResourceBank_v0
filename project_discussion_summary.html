Project Discussion Summary

Key points from our evaluation and Q&A about the Django app

1) Project Snapshot

Stack: Django 4.2, SQLite, server-rendered templates, role-based access, audit history, multilingual UI.

Strengths: Clean models, form validation, role-based access, Excel export, audit trail, and good documentation.

2) Clarifications on Architecture Terms

“View complexity”

Not UI style — it means the Python view function does many tasks at once (querying, formatting, exporting). This makes it harder to test/maintain.

“Centralized” logic

Put repeated logic in one reusable place (e.g., custom decorator or mixin for permission checks).

“Large export function”

Large = multiple responsibilities in one function. The Excel export handles filters, styling, conversions, and response creation in a single view.

3) Tests: Do You Need Them?

Not required for a small app, but highly recommended for professional habits.

  • Test form validations (e.g., viability between 0–100).
  • Test login-required views (status codes).
  • Test sample creation and model rules.

4) Business Logic vs Views

Business logic = rules/calculations like dashboard stats and export formatting. These can live in helper modules so views stay simple.

This is a “next-level improvement,” not mandatory for a working app.

5) Security & Deployment (PythonAnywhere)

What’s already good

  • Django auth (hashed passwords, sessions)
  • Role-based access control
  • Audit history

Settings to double-check for production

  • DEBUG = False
  • SECRET_KEY via environment variable
  • ALLOWED_HOSTS set properly
  • Optional: CSRF_COOKIE_SECURE, SESSION_COOKIE_SECURE, SECURE_SSL_REDIRECT

SQLite is OK for a small team, but not ideal for high concurrency.

6) PythonAnywhere Free Tier Capacity

Beginner (free) tier limits (from PythonAnywhere pricing):

  • 100 CPU-seconds/day
  • 1 web app + 1 web worker (requests queue)
  • 512MB disk

Conclusion: Likely okay for a small team with light usage, but can feel slow or hit limits if users upload images/export often. Paid tier is safer for regular daily use.

7) Future Upgrades (Next.js / Better DB)

Moving to Next.js is possible but not a simple switch:

  • Django becomes API backend (e.g., Django REST Framework)
  • Next.js becomes the frontend (rebuild templates as React pages)
  • Models and data can remain

For a beginner, keep the current Django structure until you want a modern frontend or API-first architecture.

8) Suggested Next Steps (Optional)

  • Decide if free-tier is enough for your daily usage.
  • Set production security flags in settings.py.
  • Consider a paid PythonAnywhere plan if usage grows.
  • Add a few basic tests to build confidence.
